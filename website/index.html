01

The ordinary ways pictures walk away

Right place, wrong hands

A normal <img> tag is a public URL. View-source, DevTools, or one bulk scraper later, your full-resolution master is on someone else’s storefront — metadata, quality and all.

Watermarks only go so far

Visible marks can be cropped or obscured; metadata is often stripped by re-upload. Neither controls who receives the pixels or stops an authorized viewer from capturing them.

“Disable right-click” is theatre

It annoys your customers and stops nobody. Real protection has to change what the server delivers: keep the master private, authorize each view, and apply quotas plus a width policy. Scraping can be limited, not eliminated.

02

How Archx works

  1. i.

    Masters stay off the web

    Keep originals outside every public root and declare those roots with publicDir/publicDirs. The middleware checks declared overlaps at startup; undeclared host mounts remain your responsibility. The middleware is the only intended reader.

  2. ii.

    Every view is authorized, scrambled & replay-limited

    Your authorize callback decides who may see what, and how large. The server applies the signed entitlement and configured width caps, permutes the tiles under a 128-bit-seeded plan, optionally seals them with AES-256-GCM, and issues a short-lived token with one-time claim enforcement while its spend record is retained. The default maxWidthFraction is 1, so set it below 1 when native-width pixels must be withheld.

  3. iii.

    The viewer reassembles — and poisons the exits

    Canvas/WebGL rendering with no ordinary image URL to copy. Read-back gets a decoy; capture signals may trigger a black or degraded frame. Deliveries can carry an invisible StegoMark fingerprint tied to an issuance record; in the project’s single-transform bench it recovered in 85 of 99 cases, including screenshot simulations, not in every screenshot or attack.

The honest limits

Nothing can make displayed pixels un-copyable: a determined person can photograph a screen. Archx does not claim screenshot prevention, DRM, or guarantees. What it does: removes the master from reach, makes bulk theft slower and more limited when authorization, quotas, and a preview-width cap are configured; degrades some captures, and leaves evidence in copies that can be identified. Layered friction plus attribution — that is the whole pitch, and it is the same physics every honest tool in this space lives with.

05

Use it in an afternoon

On the server

import { createArchxMiddleware }
  from '@archnemix/image-protection/server';

app.use(createArchxMiddleware({
  imagesDir: '/private/masters',   // outside public/
  publicDirs: ['/var/www/public'], // declare every static root for overlap checks
  maxWidthFraction: 0.6,           // omit native-width pixels for preview-only delivery
  secret: process.env.ARCHX_SECRET,
  authorize: async (req, image) =>
    req.user ? { maxWidth: 1600 } : false,
}));

In the page

import Archx from '@archnemix/image-protection';

Archx.load.image('#hero-photo', { id: 'aurora-valley' }, {
  tokenEndpoint: '/archx/token/',
  profile: 'elite',     // lite · performance · elite — or custom flags
  temporalInterlace: { refreshHz: 60 },
});

Three profiles set the defaults — lite spends the least CPU and memory, performance balances protection and cost, elite turns every hardening layer on — and any individual setting can still override them.

Prefer static hosting? The build CLI pre-scrambles assets for any CDN: npx archx-build. Framework-free; Express, Fastify and plain node:http all work.
