01

The ordinary ways pictures walk away

Right place, wrong hands

A normal <img> tag is a public URL. View-source, DevTools, or one bulk scraper later, your full-resolution master is on someone else’s storefront — metadata, quality and all.

Watermarks only go so far

Visible marks spoil the viewing experience and crop out. Metadata is stripped by the first re-upload. Neither survives a screenshot, and neither stops a script that harvests a thousand images an hour.

“Disable right-click” is theatre

It annoys your customers and stops nobody. Real protection has to change what the browser receives: no master file, no reusable URL, nothing worth bulk-downloading.

02

How Archx works

  1. i.

    Masters stay off the web

    Originals live outside your public folder. The only route that can read them is the Archx middleware — and it refuses to start if your masters sit inside a served directory.

  2. ii.

    Every view is minted, scrambled & spent once

    Your authorize callback decides who may see what, and how large. The server downsizes to display resolution, permutes the tiles under a 128-bit-seeded plan, optionally seals them with AES-256-GCM, and issues a short-lived token that redeems exactly once.

  3. iii.

    The viewer reassembles — and poisons the exits

    Canvas/WebGL rendering with no image URL to copy. Read-back gets a decoy, PrintScreen gets a black or degraded frame, and each delivery can carry an invisible StegoMark fingerprint naming the recipient — recoverable from a screenshot of the leak.

The honest limits

Nothing can make displayed pixels un-copyable: a determined person can photograph a screen. Archx does not claim screenshot prevention, DRM, or guarantees. What it does: removes the master from reach, makes bulk theft slow and low-quality, degrades casual captures, and leaves evidence in the copies that do escape. Layered friction plus attribution — that is the whole pitch, and it is the same physics every honest tool in this space lives with.

05

Use it in an afternoon

On the server

import { createArchxMiddleware }
  from '@archnemix/image-protection/server';

app.use(createArchxMiddleware({
  imagesDir: '/private/masters',   // outside public/
  secret: process.env.ARCHX_SECRET,
  authorize: async (req, image) =>
    req.user ? { maxWidth: 1600 } : false,
}));

In the page

import Archx from '@archnemix/image-protection';

Archx.load.image('#hero-photo', 'aurora-valley', {
  mode: 'vault',        // shield · vault · custom flags
  temporalInterlace: { targetFps: 60 },
});

Prefer static hosting? The build CLI pre-scrambles assets for any CDN: npx archx-build. Framework-free; Express, Fastify and plain node:http all work.
